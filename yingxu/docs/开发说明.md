# 映序开发说明

[返回映序](../README.md) · [功能指南](功能指南.md) · [安装与运行](安装与运行.md) · [接口约定](../API_CONTRACT.md)

映序面向本地视频创作项目管理。当前公开版本 **0.3.5**，包含源码、测试和 Windows 桌面入口；测试应使用临时夹具，不操作真实项目、外部技能或用户正在运行的应用。

## 代码结构

| 位置 | 职责 |
| --- | --- |
| `server.py` | 本地 HTTP 接口、媒体请求、上传、文档与本机操作 |
| `launcher.pyw` | 运行环境选择、服务启动与浏览器入口 |
| `yingxu/store.py` | SQLite 索引、项目与文件元数据、搜索 |
| `yingxu/organize.py` | 实际文件夹、文件移动与可恢复删除 |
| `yingxu/jobs.py` | 后台扫描与缩略图任务 |
| `yingxu/docx_io.py` | DOCX 普通正文读写与结构保护 |
| `yingxu/skills.py` | 外部技能发现、自建 SKILL、项目绑定 |
| `yingxu/context.py` | 项目进度与文件索引的 Markdown / JSON 导出 |
| `yingxu/paths.py` | 用户数据路径、文档目录与环境覆盖 |
| `frontend/` | 原生 HTML、CSS、JavaScript，浅色中文工作区 |
| `desktop/` | WinForms + WebView2 桌面壳、拖出文件桥、构建与测试 |
| `tools/` | 性能复测、打包与隔离发布核验 |
| `tests/` | 后端、目录组织、文档、HTTP 和协作等回归检查 |

后台核心使用 Python 标准库和 SQLite；Markdown 编辑器在开发构建阶段使用锁定的 npm 依赖生成本地 bundle，不加载 CDN 或远程字体。源码运行可配置 Pillow / FFmpeg；完整发布包已自带 Python、Pillow、FFmpeg 和固定 WebView2，使用者无需安装 Node.js/npm。

## 数据原则

- 文件仍是普通项目文件或明确登记的外部引用，数据库维护标签、状态和关联。
- 项目内移动同时调整真实路径和引用记录；外部引用移动只改变组织归属。禁止覆盖同名目标，批次失败需要回滚。
- 文档保存先检查 etag，再保留原版本；外部修改冲突不直接覆盖。
- 删除使用应用内批次回收站，原文件保留。恢复目录 / 项目不能恢复更早独立删除的内容。
- 外部 SKILL 只读，隐藏不删除来源；自建技能可编辑并保留版本。
- 项目交接采用 Markdown、JSON 与 JSONL，包含生成时间。后台合并变更，旧任务不能把已恢复项目写成回收状态。

## 素材量增长时的策略

| 问题 | 当前处理 |
| --- | --- |
| 文件卡片越堆越多 | 服务端查询分页，界面每页 48 项文件、12 项文件夹 |
| 列表返回大量正文 / 生成工作流 | 列表返回摘要，打开文件后按需读取全文和完整元数据 |
| 每次同步重新解析全库 | 增量扫描，未变化文件跳过正文解析，保留组织和手工信息 |
| 目录匹配随文件量乘倍增长 | 文件夹路径索引加祖先查找，避免逐文件遍历所有文件夹 |
| 一次生成太多缩略图 | 有界任务队列、有限后台并发和媒体处理超时 |
| 大视频上传占满内存 | 按块写入临时文件，发布前校验目录，异常清理未完成内容 |
| 播放视频先读完整文件 | HTTP Range 响应，浏览组件按需读取 |
| 输入搜索不断刷新 | 输入防抖，取消或忽略过时响应 |
| 大型 AI 交接快照 | JSONL 文件索引逐行导出，前端不常驻完整大索引 |

普通列表与中文检索的性能基准使用十万条合成索引；这只测索引、查询和导出路径，不包含真实媒体解码、网络盘延迟或系统冷缓存。可用下面的工具在自己的设备上复测，不将某一次耗时当成所有机器的保证。

## 本地检查

在独立开发副本中运行，需 Python 3.11+；编辑器构建与前端检查需要现有 Node.js/npm。先在锁文件所在目录安装并构建：

```powershell
Set-Location tools/markdown-editor
npm ci --ignore-scripts --no-audit --no-fund
if ($LASTEXITCODE) { throw 'Markdown editor dependency installation failed' }
npm run build
if ($LASTEXITCODE) { throw 'Markdown editor bundle build failed' }
Set-Location ../..
```

构建产物为 `frontend/live-markdown.js`、`frontend/live-markdown.manifest.json` 和 `frontend/live-markdown.LICENSE.txt`。直接依赖及构建工具固定版本写在 `package.json`，完整依赖树和包完整性写在 `package-lock.json`；发布时保留许可证、清单与构建输入，不打包 `node_modules`。完整包使用现成 bundle，启动时不安装依赖。

之后运行回归检查：

```powershell
python -B -m unittest discover -s tests -v
node --check frontend/app.js
node tests/frontend_live_markdown.cjs
node tests/frontend_markdown_integration.cjs
python -B tools/benchmark.py --help
```

桌面构建使用现有 .NET Framework 编译器与已核对来源的 WebView2 SDK；具体参数先查：

```powershell
python -B desktop/build.py --help
```

桌面原生拖放需另外在目标接收软件中验证。路径与桥接单元测试只能确认本工具的边界检查，不能证明所有剪辑软件均接收成功。

## 打包与发布

发布使用显式文件清单，保留历史版本；不把应用数据、数据库、备份、浏览器配置、个人项目、外部 SKILL 或本机路径记录放进 ZIP。

```powershell
python -B tools/prepare_runtime.py --cache 'D:\YingXuBuildCache' --download
python -B tools/package_release.py
python -B tools/verify_release.py releases/YingXu-v0.3.5-Windows-x64.zip
```

Windows ZIP 以单个 `YingXu/` 目录为根，包含源码、文档、测试、桌面入口及许可；公开下载链接指向程序包本体。发布前验证文件清单、字节数、SHA-256、ZIP 完整性、解压后的独立运行与默认目录，不调用真实创作项目作为测试夹具。

软件说明和发布文档必须区分已实现功能、真实操作验证及当前边界，不用示意图冒充软件截图，也不将无订阅等同于依赖已捆绑。

## 本地接口与安全边界

服务只监听 `127.0.0.1`；写请求有本地来源和会话校验。路径访问先验证已登记项目 / 文件，不任意运行上传的文件。Markdown 预览禁用原始脚本，DOCX 读写对压缩包与结构设限。

接口定义见 [API_CONTRACT.md](../API_CONTRACT.md)。向 Codex 等工具交接通过用户可读的项目文件完成，不使用账号凭据、远程自动执行或私有登录缓存。

## 后续方向

当前优先维护目录整理、文档保存、恢复和大素材库的可靠性。完整 Word 排版、剪辑时间线、内嵌三维编辑、语义搜索与多人同步均未实现，未来若加入需独立评估格式兼容、性能和数据迁移成本。

原创代码为 [MIT](../LICENSE)，WebView2 按[随附微软许可](../desktop/WebView2-LICENSE.txt)分发。

完整包的运行时来自 `tools/runtime-lock.json` 锁定的发行档案；构建清单与包内文件逐项校验。`runtime/` 为忽略目录，不允许从已使用的运行环境打包。验证会清空外部工具搜索路径，并实际生成图片和 H.264 视频、请求两类缩略图。固定 WebView2 在独立临时配置中启动验收。

### 0.3.5 框选与验证边界

前端 `marquee.js`/`marquee.css` 仅在资源滚动区工作。手势开始缓存本页可见卡片几何，移动合并为单个待执行动画帧，只有选择集合改变才调用 `updateSelection`；停止或取消即停止帧调度。没有持续后台任务。回归命令：`node tests/frontend_marquee.cjs`。

已实测映序窗口内触发、其他应用位于前台时的后台快捷键触发、实际屏幕上的合成区域选择、项目附件保存和 Markdown 图片内嵌；575×250 像素截图与剪贴板图像逐像素 RGBA 匹配。正常关闭至托盘后，全局快捷键能唤起截图遮罩已实测；托盘状态下的选区完成及真实 Esc 取消尚未验收，不同 DPI 的多屏组合亦未实测。

素材组成员查询使用 `CROSS JOIN` 固定从有界成员集合访问素材主键，避免 SQLite 为每组重复扫描项目全表。同一份 10 万条索引、10 组各 20 名成员的 7 次复测，P50 从 1469.24 ms 降至 2.683 ms，前后 JSON 摘要一致。极限 500 组各 200 名成员的全项目组快照 P50 为 199.63 ms、回包约 4.90 MB；当前 `loadItems()` 仍会获取全项目组快照，不能把此结果与普通每页 48 条资源混为一谈。前端已消除修改后的重复快照 GET 与相同 DOM 的重复绘制；局部基准不等同于完整桌面性能验收。
