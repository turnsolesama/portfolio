# 映序安装与运行

[返回映序](../README.md) · [功能指南](功能指南.md) · [开发说明](开发说明.md)

当前版本 **0.3.6**，Windows x64 完整包自带运行环境。完整解压后双击 `YingXu.exe`；保留 `runtime/` 和所有程序文件。

## 运行要求

**Windows 10 22H2 / Windows 11 x64**。这些系统自带所需 .NET Framework；正常使用无需另外安装组件、配置 PATH 或运行安装命令。

| 随包组件 | 作用 |
| --- | --- |
| CPython 3.13.15 | 本地后台、索引与文件管理 |
| Pillow 12.3.0 | 图片缩略图、尺寸、生成信息及示例图片 |
| FFmpeg 9.0.1 | 视频缩略图及示例视频 |
| WebView2 152.0.4191.62 x64 | 工作台渲染、媒体预览、桌面交互 |

系统已装相同或更新 WebView2 时会优先使用；否则直接运行随包版本。不会自动下载、修改系统 Python 或 PATH。完整包增大了下载与磁盘占用，不增加每次启动的解压步骤，媒体处理仍按需进行。

功能保持原有边界：视频直接播放由 WebView2 支持的编码决定；Word 仅编辑正文段落；桌面拖出需目标软件支持文件接收。Windows 7、32 位系统和 ARM64 原生包不在本次支持范围。

[组件来源及许可证](../THIRD_PARTY_NOTICES.md)。从 Git 源码运行的开发者仍需自行配置环境；Node.js/npm 只用于构建 Markdown 编辑器与开发测试，完整包运行不需要安装。

## 首次启动

1. 从[版本与校验](https://github.com/turnsolesama/portfolio/blob/main/yingxu/releases/README.md)下载 Windows 程序包，完整解压到一个可写目录。
2. 保留完整 `YingXu` 目录，双击 **`YingXu.exe`**。
3. 选择创建项目或创建示例项目。示例内容为明确标注的演示资料，不会导入别人的创作文件。
4. 要做桌面入口，可为 `YingXu.exe` 创建快捷方式，工作目录设为该程序文件夹。

`start.vbs` 是备用启动脚本，仍会打开桌面 EXE。若需要普通浏览器界面，在程序目录运行 `python -B launcher.pyw --no-browser --no-dialog`，再自行打开 `http://127.0.0.1:8791/`。服务只能在本机访问；桌面原生拖出功能需使用 EXE 窗口。

## 默认数据位置

| 内容 | 默认保存位置 |
| --- | --- |
| 索引、缓存、编辑版本、自建 SKILL | `%LOCALAPPDATA%\YingXu` |
| 新创建的项目 | Windows“文档”已知目录中的 `YingXu\Projects` |
| 项目文件、分类目录与 AI 交接 | 每个项目自己的目录 |

Windows“文档”支持系统重定向，例如用户迁移到其他盘或使用系统配置的文档位置。映序读取系统的文档目录，不写入作者机器上的固定盘符。

**备份需要同时包含项目和应用数据目录。** 普通文件保存在项目 / 外部来源中，标签、制作状态、关联及编辑历史等还依赖应用数据。只复制项目文件不等同于完整备份工作台。

## 自定义目录或 Python

以下环境变量接受绝对路径：

| 变量 | 用途 |
| --- | --- |
| `YINGXU_DATA_DIR` | 指定应用数据目录 |
| `YINGXU_PROJECTS_DIR` | 指定新项目的保存根目录 |
| `YINGXU_PYTHON` | 指定用于启动的 Python 解释器完整路径 |

建议在首次启动前设置。改环境变量只改变目录选择，**不会自动迁移旧项目、复制旧数据库或合并两套数据**。已有项目时先备份，再按明确的迁移计划处理。临时设置仅由对应进程会话继承；长期使用需要用户自行配置环境变量，并重新打开程序。

更改 `YINGXU_PROJECTS_DIR` 前，先保存内容、等待导入完成并停止后台，再用新配置打开。服务复用按数据目录识别，已经运行的后台不会自动载入新的项目根目录。

## 窗口、后台与完全停止

关闭桌面窗口会保留后台服务，让已开始的索引任务继续。再次打开程序会连接本机服务。完全停止时，先保存内容，等待导入完成，再在程序目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop-YingXu.ps1
```

重新双击 EXE 即可再次启动。不添加开机自启，也不会在启动时自动生成图片或视频。

开发或诊断时，可在程序目录直接启动后台：

```powershell
python -B launcher.pyw --no-browser --no-dialog
```

完整启动参数和便携运行细节以包内 [RUNNING.md](../RUNNING.md) 为准。

## 更新已有版本

1. 保存正在编辑的文档，等待导入 / 索引任务完成。
2. 关闭映序窗口，并使用原程序目录的 `Stop-YingXu.ps1` 停止后台。
3. 备份项目与完整应用数据目录。已停止的数据库连同应用目录一起备份；运行中的 SQLite 应使用数据库 backup API，不要忽略 WAL 只复制主文件。
4. 将新版完整解压到新目录。保留旧版文件作为短期回退副本，默认应用数据目录继续使用原位置。
5. 双击新版 `YingXu.exe`，确认项目列表、文件和制作信息正常后继续工作。若之前使用了自定义环境变量，保持同一配置。

仅覆盖前端或只关闭窗口不足以让旧后台加载新版 Python 代码，更新时需要重启后台。

## 常见问题

| 现象 | 检查方式 |
| --- | --- |
| EXE 提示没有找到 Python | 重新完整解压新版，确认 `runtime/python.exe` 存在；自定义 Python 仅供开发者使用 |
| 提示 WebView2 Runtime 缺失 | 重新完整解压新版，确认 `runtime/webview2/` 没有遗漏；不要只复制 EXE |
| 页面打开但看不到刚更新的界面 | 保存，从托盘菜单退出窗口并停止旧后台，再从新版目录打开 |
| 端口占用或启动失败 | 检查是否已有映序实例；不要随意结束占用端口的其他程序 |
| 没有缩略图但文件已导入 | 查看“使用指南”中的组件状态；完整包已自带 Pillow / FFmpeg，文件损坏、超大图片和不支持格式仍可能没有预览 |
| 拖到其他软件没有反应 | 目标软件可能不支持该拖放格式；使用右键“打开所在文件夹”后从资源管理器操作 |
| 外部改过文件，工作台信息还是旧的 | 点击“同步项目文件”；编辑冲突时先处理两份修改，再保存 |
| 换了数据位置后项目列表为空 | 检查自定义目录是否一致；配置新目录不会自动搬迁原数据 |

## 移除软件

先保存并停止后台，再移除程序文件夹即可。程序、应用数据和项目目录分开放置，删除程序本身不会删除作品。若不再需要应用数据，先核对其中的编辑版本、自建 SKILL 和索引记录，再自行决定如何保留。

初次删除只把记录移入映序回收站，原件仍在；再次清理映序回收站时，项目内原件会移入 Windows 回收站。外部引用保留原件。卸载前也可从设置撤销“打开方式”候选。
