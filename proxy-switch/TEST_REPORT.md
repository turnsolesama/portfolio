# FlowSwitch 3.7.2 候选维护验收

2026-09-11，Windows x64 / Windows PowerShell 5.1。候选在独立工作副本构建，未覆盖当前安装、桌面入口或个人规则；未发布到 GitHub。正式软件可用性及另一台电脑真实登录仍待验收。

## 本轮得到的关键证据

- 显示误报：Windows CIM 多状态查询在某个状态没有记录时抛出 NotFound。只读实测 Listen + DeleteTCB，Stop 模式整轮赋值为 0 条，非中断收集仍有 43 条。原代码会把这种情况当成正常空表。现改为单次读取完整 TCP 表后筛选；真正读取失败仍显示未知。
- 手动重新选择 A：原普通规则同步保留备用 B 的逻辑也作用于手动重选，导致 A 恢复后仍走 B。现在明确手动选择重置首选组，后台刷新及无关规则修改仍保留有效备用。
- 独立入口停止：此前即使已经配置独立分流，点击统一切换也直接因未监听失败。现在显式切换可启动已配置入口，再核验目标和真实请求后提交；不会仅打开窗口就改网络，也不自动迁移外部引擎。
- 出口真假：真实 HTTP 可用但 selector 与所选出口不符时拒绝成功并恢复原线路。默认线路的程序可以打开预览重连菜单，未知／未加载规则仍受保护。
- IDE 启动链：已有 launch 记录改线路不再变为单 EXE 引擎规则。真实临时父子 EXE 验证下一次启动从 A 改为 B 的参数和环境继承；运行中的环境不会被改写。
- 入口与诊断：失效旧快捷方式明确识别、显式修复保留原始备份及外部编辑；后端初始化失败使用短错误码和单个有界本地报告；Google 诊断读当前系统入口。EXE 和 UI 版本由同一变量生成。

## 修复依据

3.7.0 的损坏锁复现中，A 已退出且 B 健康，等待 12 秒仍不能接替；只删除隔离测试锁后恢复。3.7.1 不按文件年龄直接删除锁，改为在禁止其他写入和删除的文件句柄内核对原内容、PID 与启动时间，再写入新持有者。活跃旧版写入者保持不动，正常无冲突操作不启动额外恢复进程。

并发测试还覆盖多个恢复者争用同一旧锁；释放操作等待短暂占用的恢复句柄，避免失败后遗留仍存活的持有者。停止后重开遇到损坏 singleton 时，通过已有监督进程记录判断旧会话，随后走受控锁恢复。

这些故障注入不等于确认用户历史断网的唯一原因。另一台电脑的硬件兼容性、真实登录、长时间稳定性和性能仍须按 [验收约定](ACCEPTANCE.md) 分别确认。新版本不新增 TUN、自动结束应用、复制订阅或默认全失败直连行为。

## 本次复现并修复的问题

旧 MSIX 路径与新版进程被拆成两行；连接读取失败被当成空闲；SynSent 丢失目标端口；父程序误汇总有独立规则的子程序；配置或连接 API 部分失败使全部证据丢失；规则被前置 MATCH 遮蔽仍被算作已加载；成功写入后的界面刷新错误丢失操作结果。

恢复方面，已复现停止中重新启动复用旧 child、恢复环境变量时覆盖外部新值、旧 watchdog 等锁后恢复新会话、自有入口被当作可恢复原代理、残留更新锁阻止接替，以及修复 EXE 路径使共享出口回跳。这些场景均有对应回归。普通规则写入及回滚也在引擎锁内核对状态和配置版本。

正常刷新只进行观察与已授权的代理发现。修复程序路径需要明确核对计划；计划过期、身份有歧义、目标已存在记录或外部修改时拒绝覆盖。原线路和自有快捷方式原始备份保留；外部修改的快捷方式保持原样。

## 验收边界与另一台电脑复测

本机与隔离测试通过不等于另一台电脑的登录验收。原错误只能确认当时本机代理入口不可用，不能倒推出历史内核是正常退出还是崩溃。

未自动结束应用、开启 TUN、复制订阅或收集令牌。核验程序包和公开 SHA-256 见 [下载与校验](releases/README.md)；私有实机日志与备份不随包发布。
