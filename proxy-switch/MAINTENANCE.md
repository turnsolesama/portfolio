# FlowSwitch 3.8.0 核心重构候选维护记录

更新于 2026-09-12。3.8.0 的重点是通用切换链，而不是给单一 IDE 增加特殊规则。它仍是候选版本，真实跨电脑使用和 IDE 登录尚未验收；当前状态见 [验证记录](TEST_REPORT.md)。

这次调整的核心是让受支持程序及继承代理环境的子进程记住稳定的 FlowSwitch 入口，A、B 和直连作为入口后面的出口切换。普通操作统一调用适用的后端；用户不再需要先理解系统代理、启动参数和引擎规则三个内部模式。旧路径修复、外部修改保护和显式重连继续保留。

网站例外让同一浏览器的不同域名分别直连或走代理。例外规则会在统一切换时保留，并按范围和域名具体程度确定优先级。仍缓存旧 A 地址的运行进程需要首次接入；工具没有实现任意现存程序、外部浏览器或系统服务的透明接管。

本轮还修正了界面与行为不一致：普通打开不再自动启动已停止的独立入口；默认代理暂停不再写成全部流量停止；自动接替按实际开关显示；未配置入口时说明普通统一切换会建立入口。短时隔离被动窗口回归及相关真实控件检查已通过，不能因此代替长期运行验收。

完整静态与单元套件已通过，离线撤离单元 39 项通过。先前真实入口、生命周期和父子程序切换检查已通过，但最近离线迁移事务变更后的对应复测，以及完整离线迁移集成，编写本节时仍待完成记录。最终包必须从最终源码重新构建并核验。

之前多次版本更新主要完善了托盘、恢复、身份和显示等局部能力，没有充分验证用户实际经历的连续切换与登录流程。3.8.0 通过固定入口和统一操作处理这项结构缺口，但不能据此预先宣称另一台电脑或真实账号流程已经修好。

以下原正文属于 3.7.2 及更早版本的维护过程。旧模式选择、待开发计划、当时测试证据和“明天”步骤均按历史保存，不作为 3.8.0 当前实现或验收通过声明。

# FlowSwitch 3.7.2 维护候选

本轮从 GitHub 已核验的 3.7.1 源码创建独立开发副本。现有安装、桌面入口、用户网络设置与个人规则不随构建覆盖。候选尚未作为正式新版发布。

## 为什么多次改版仍没有满足原始需求

| 阶段 | 实际改动与缺口 |
| --- | --- |
| 3.1 | 引入受支持程序的启动参数和子进程代理环境；需要从托管入口启动 |
| 3.2 | 普通程序指定改为单 EXE 引擎规则，固定入口和确认重连；不自动等于父子进程整体路由 |
| 3.3 | 工作区、主题、缩放和滚动显示 |
| 3.4–3.5 | 自带独立入口、运行组件和备用线路接替 |
| 3.6 | 关闭到托盘、内核有限自动恢复、停止时恢复配置 |
| 3.7–3.7.1 | 程序身份与升级路径、观察状态、并发文件保护、异常锁恢复 |

这些功能确有实现，但没有充分验收“真实用户入口启动 IDE → 联网子进程 → 浏览器登录 → 回到 IDE → 来回切换”整条链。单元检查或内核测试通过不能抵消这个交付缺口。

## 本轮修复与复现

0. Windows CIM 多状态 TCP 查询遇到不存在的状态会抛出 NotFound；原整轮赋值丢弃了已有监听／连接，且将其当成可用的空快照。已在本机只读复现：Listen + DeleteTCB 查询在 Stop 模式得到 0 条，非中断读取保留 43 条监听。修复为单次读取后筛选，覆盖空闲 SynSent 情况。此证据支持显示误报原因，不等于证明另一台电脑的全部故障。
1. 自动接替保留备用的逻辑也应用于手动再次选首选，造成仍走备用却显示已设置首选。现在只有明确手动切换重置该首选组，普通刷新／规则修改保持备用。
2. 已停止独立入口时，统一切换直接被未监听保护阻止。现在已配置独立分流、没有活动会话时，点击切换会启动自己的入口并核验目标后提交。第三方引擎离线仍不能偷偷换端口或迁移。
3. 通用代理检测成功不能说明所选出口已生效。提交前增加规则与 selector 核验，出口不符则失败回滚。
4. 旧启动代理记录在普通菜单改线时变成单 EXE 分流，丢掉原启动适配语义。现在保持模式，并提供明确的父子启动代理选项。
5. 旧 .lnk 只要符合历史记录就被称为有效，未核对实际后端是否仍存在。现在检查版本入口、提供保留所有权的显式修复。
6. 后端初始化失败发生在启动捕获之外，隐藏进程可能只输出长堆栈。现在给短错误码与脱敏本地报告。
7. 默认线路的已运行程序无法打开重连菜单，诊断按钮使用了配置入口而不是当前系统入口。已分别修复。

## 明天另一台电脑的验收

1. 记录软件版本、入口模式及 A/B 两条已知可用代理。先单独确认两条代理的目标网站可用。
2. 已配置独立模式：停止服务后重新打开，选择 A 并点统一切换。确认入口就绪后再开 IDE；依次 A→B→A→直连→B。直连仅在目标本身可直连时用于联网验收。
3. 每次记录首选、当前出口、入口地址以及 IDE 新请求是否成功；旧连接需要预览后明确确认重连。不能只观察下拉框。
4. IDE 采用启动代理时，从该模式提供的代理入口完整重开；检查主程序和联网子进程。已有独立后台服务或不读取代理环境的程序另列为未覆盖。
5. 完成一次真实 Google 登录：浏览器成功后 IDE 必须显示登录账号并能发请求。不能用 HEAD 200/404 代替。报告勿包含登录 URL、授权码、Cookie 或令牌。
6. 关闭到托盘后请求继续成功；显式停止后恢复设置。保留外部后来修改的配置，不自动结束应用。

本轮没有实现任意已运行进程的透明流量迁移，也没有自动接管外部浏览器／系统服务。若这部分是必需能力，后续需要程序专用固定入口等结构调整及单独验收，不能靠补进程名称规则保证。

实际执行的测试和失败排查记录见 TEST_REPORT.md。
