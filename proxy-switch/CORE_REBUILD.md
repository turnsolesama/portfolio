# 3.8.0 核心重构与验收边界

本轮围绕通用切换重构，不以某一个 IDE 的登录成功作为产品能力证明。

## 原先为什么仍然难用

旧版逐步修过托盘、内核恢复、状态采集、包身份识别、备用线路保留和切换回滚，但系统代理、单 EXE 引擎规则、直接绑定上游端口的启动代理仍是不同入口。界面能保存 B，并不意味着已经运行的联网子进程会放弃 A。此前的隔离测试不足以覆盖“同一批父子进程实际请求改线”和“同一浏览器混合直连/代理网站”两条端到端链路。

## 现在的行为

- 明确统一切换准备流向固定入口，程序切换自动选择已支持的原生接入方式。
- 每个已接入程序保留独立本地 mixed 端口。进程启动参数、子进程代理环境不再随 A/B 改线而改变。
- 该程序的独立 selector 负责新连接出口及有限自动接替；无关网站修改不会使它回抢首选。
- 网站规则与程序入口保存在同一 v3 状态事务中，支持全局/程序范围、精确域名/子域、代理/直连；范围及具体度决定优先级。
- 主窗口关闭驻留托盘；快捷方式启动由常驻 UI 接收并等待入口就绪。有限内核恢复、外部设置归属检查和回滚继续保留。
- 切换结果与连接观察分开；未知不会变成“没有连接”。移除活跃或状态未知的固定入口会被拒绝，选择“跟随”可保留入口并取消专用出口。
- 旧外部分流引擎已停止时，明确切换会先备份并核对旧托管规则；仅能证明属于流向的部分允许离线分离，再建立自有入口。遇到未知改动或配置竞争会保留现场并说明原因。
- 单个程序固定端口被占用时，只标记该程序入口异常；公共入口和其他可用程序继续工作，不会因一个程序端口异常反复重启全部服务。

## 必须理解的范围

首次接入仍需要完整重开一次原应用；已经记住旧代理 A 的进程不会被远程改写内存或环境。此后，接入稳定入口的父子进程可以一起改线。外部浏览器若复用旧进程，仍需按同样规则接入或重开。忽略系统/原生代理的流量不保证接管，本版本不启用 TUN、不结束用户应用。

短时 TCP、UDP/QUIC、独立隧道与宿主重启后丢失关系证据的孤儿进程，可能无法完整归组。入口实际转发与父子关系观察是不同能力。

浏览器登录页面成功、回调收到响应、客户端向令牌端点发请求，是独立阶段。本版本不读取登录链接、授权码或令牌；Google 固定端点的无凭据诊断不能证明登录成功。真实登录仍需在用户电脑完成。

## 真实应用复验

1. 保留旧版和数据备份，通过旧版托盘停止服务，使用候选包。
2. 统一选择 A，为浏览器/IDE 设置线路，首次从流向完整重开；记录实际入口状态和联网子进程是否已观察到。
3. 同一批进程保持运行，在 A、B、直连间切换，刷新请求；再退出上游 A 并切 B。已有长连接需要刷新或明确预览重连。
4. 程序默认 B，为只能直连的测试网站添加直连例外，同时打开需要代理的页面；测试更具体域名覆盖宽规则。
5. 完整测试浏览器登录、回到客户端、客户端登录状态。失败时只记录时间、阶段和脱敏错误，勿提交登录链接或令牌。
6. 关闭流向主窗口，验证托盘和请求持续；明确停止服务后验证外部后来修改的代理设置保留。

已执行的自动验证与结果见 TEST_REPORT.md。原安装及其配置未由重构测试改写。
