流向 FlowSwitch 3.5.1 — 自带运行组件版

适用：Windows 10 1809 / Windows 11 的 64 位电脑，保留系统自带的 Windows PowerShell 5.1、.NET Framework 4.x 和 curl.exe。32 位 Windows、Windows 7/8 和原生 ARM64 包不在本次交付范围内。
完整解压后双击 FlowSwitch.exe，保留整个 app 目录。无需另装 Node.js、npm 或 Clash，也无需配置 PATH。首次启动不下载运行组件，不要求管理员权限。
程序自带 Node.js 24.19.0、mihomo 1.19.29（标准及兼容构建）及许可证；首次启用时将独立运行文件放入本机数据目录。已有用户继续使用之前已验证的本机内核副本，避免升级悄悄更换内核。
程序不提供代理服务、订阅或账户。要使用代理出口，仍需你自己的可用 HTTP / SOCKS5 代理（可以是其他客户端，也可以是远程入口）。

1. 添加代理入口，或打开自己的代理客户端让 FlowSwitch 发现入口。
2. 关闭其他客户端的 TUN、系统代理和代理守卫开关，保留它们作为上游运行。
3. 点击「代理管理 → 启用独立分流」。入口默认从 18790 选择空闲回环端口。
4. 顶部选择首选线路并统一切换；也可以按程序设置线路。
5. 「自动接替设置」调整全局备用顺序，每个程序先使用自己的首选线路。

自动检测会验证代理隧道与外网响应，每个请求最多等待 6 秒；连续三轮失败后接替。确认本地代理端口已退出且存在检测成功的备用时提前接替。检测程序自身出错不会被当作全线断网。修改无关程序规则或重载时保留当前备用出口；首选恢复后继续使用可用备用，避免反复跳转。

顶部显示首选与当前出口，操作记录显示最近一次自动接替及原因。本机 gateway/failover-events.json 最多保留 100 次接替，只记录线路标识、时间和原因。全部代理失效时默认暂停，可在自动接替设置中允许直连。切换主要影响新连接，旧连接可能需要右键程序预览并确认重连。检测站点可达不保证每个网站或账号都可用。忽略系统代理的软件仍需配置使用固定入口；本模式不自动开启 TUN。

关闭 FlowSwitch 时先恢复仍归属本会话的系统代理与用户代理变量，再关闭独立内核。原本的本地代理已退出时恢复直连。界面或内核崩溃由独立恢复进程处理，断电残留由下次登录恢复。其他软件后来的网络设置会保留。
恢复直连不能使本来就需要代理的网站变为可直连；已经缓存旧代理地址的软件可能需要手动重开。

本机配置、运行副本、日志和备份位于 %USERPROFILE%\.proxyswitch，更新时不会随包覆盖。不要删除或搬移正在运行的程序目录；先正常退出，等待网络恢复后再移动。
新电脑直接使用整个程序文件夹，并配置那台电脑的代理入口。不要照搬另一台的内核路径、订阅或账户文件。
公开 GitHub 下载链接尚未自动更新。构建来源、锁定版本、许可证和内核源码见 THIRD_PARTY_NOTICES.md 与 app/runtime。
