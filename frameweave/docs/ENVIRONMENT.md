# 环境识别与缺失检查

FrameWeave 自动查找已有本地推理服务，再检查当前工作流实际需要的节点、模型和输入。客户端保持轻量，不附带 CUDA、PyTorch、模型权重或整套 ComfyUI。

点击画布的“环境检查”、顶部引擎状态或生成节点的“检查环境”，打开“环境中心”。选中具体生成节点再检查，可以得到对应 H3、Krea、SDXL、API 图或工作流包的依赖结果。

## 连接已有环境

1. 打开“环境中心”，查看“可用推理服务”候选。确认目标后点击“使用此后端”；不会因为扫描发现服务而自动切换。
2. 若安装记录下列出已有模型目录，可点击“填入模型目录”。此操作打开设置供你核对，保存后才生效。
3. 未发现目标时，打开右上角设置，填写“推理服务地址”“模型目录”和可选的“ComfyUI 安装目录”，点击“保存并检查连接”。
4. 回到环境中心点击“重新扫描与检查”。修改配置或启动推理服务后，可以再次检查；短时间连续操作可能复用扫描缓存。

有排队或运行任务时不能切换推理后端，先等待任务完成或取消本客户端的相应任务。安装目录、模型目录和服务地址分别描述文件位置与连接目标，填写目录不会启动推理程序。

| 设置 | 应填写什么 | 用途 |
| --- | --- | --- |
| 推理服务地址 | 已有 ComfyUI 的本机回环 HTTP 地址，例如 `http://127.0.0.1:8188` | 获取服务状态、节点定义并提交任务 |
| 模型目录 | 已有模型根目录，每行一个 | 定位当前所选模型并检查文件结构，不移动模型 |
| ComfyUI 安装目录（可选） | 同时包含 `main.py` 和 `comfy` 文件夹的安装根目录，每行一个 | 在服务未运行时尝试关联 Python 文件和依赖元数据 |

安装目录设置保存在 `comfy_roots`；源码或命令行启动可重复使用 `--comfy-root` 指定安装目录。`--model-root` 对应模型目录，两者不要混用。自定义安装不在自动发现范围时，显式填写安装目录比反复扫描更有效。

## 自动识别范围

自动发现使用有数量和超时限制的候选集合，不进行全盘扫描。

| 检查对象 | 当前范围与依据 |
| --- | --- |
| 本机服务 | 当前配置地址、已识别 ComfyUI 进程的端口，以及常见端口 `8188`、`8189`、`8190`、`8000`；最多探测 12 个候选 |
| Windows 进程 | 有限读取 Python、ComfyUI 和已知桌面宿主的进程信息，结合安装文件结构确认关联；非 Windows 或无法读取时标记待确认 |
| 安装目录 | 用户显式填写的 `comfy_roots`、已识别进程关联目录、用户目录下少量常见 ComfyUI/便携版位置，以及 Windows 已知安装登记；最多保留 12 个安装 |
| Python 文件 | 当前已识别进程的解释器，以及安装附近常见 `.venv`、`venv`、`env`、便携 Python 和已知宿主布局 |
| 依赖元数据 | 关联环境中 `torch`、`torchvision`、`torchaudio`、`safetensors`、`numpy`、`comfyui_frontend_package` 的包元数据 |
| GPU 与驱动 | 通过固定参数的 NVIDIA 驱动查询获取可见设备；目标后端的设备报告另行检查 |
| 模型目录提示 | 已确认安装的 `models` 目录，以及进程明确引用的模型路径配置中的简单绝对 `base_path` |

复杂 YAML、相对配置路径、多级映射、未运行的任意自定义安装及自定义环境布局可能无法自动推断。此时可以手动补充目录。找到其他应用的安装或模型位置只是本地识别结果，不会修改原软件。

发现过程只读：会发出本机 HTTP 状态请求，读取有限目录、安装登记及包元数据，并运行固定参数的系统进程/驱动查询。不会执行发现的 Python 解释器，不会导入其包，不会执行用户脚本，也不会安装、下载、迁移资产或停止应用。

## 怎样理解检查状态

| 状态 | 表示什么 | 下一步 |
| --- | --- | --- |
| 就绪 `ok` | 当前检查取得了相应证据，例如节点已注册 | 继续核对其他项目；仍需真实生成验证 |
| 缺失 `missing` | 在明确检查范围内没有所需内容，例如在线后端未注册所需节点 | 核对所选环境及官方依赖，再制定补齐方案 |
| 错误 `error` | 已发现不合法或不兼容条件，例如模型架构不符、API 图为空、文件结构无效 | 修正配置或文件问题后重查 |
| 提醒 `warning` | 有限制或需要进一步验证，例如目录范围不完整、未做全文件哈希 | 阅读说明，结合实际工作流确认 |
| 待确认 `unknown` | 当前证据不足，例如后端离线或进程信息不可读 | 先连接服务或补充明确目录，不要直接重装 |

**未连接不等于未安装。** 后端离线时，节点和模型枚举标记为待确认，不会把整套环境误报成缺失。后端已列出模型但在所选目录未定位，也可能只是目录范围不完整。

Python 文件存在、包元数据存在、GPU 驱动可见和后端在线是不同证据。元数据不能证明 `torch` 能成功导入，也不能证明 CUDA 可执行；未找到包元数据同样不能直接证明包不能导入。PyTorch 运行时与 CUDA 判断优先参考目标后端报告，缺少相应证据时保留待确认。

静态就绪表示后端在线，且检查中没有缺失、错误或未知项。它不代表已经完成 GPU 生成，不保证显存足够、速度达标或画面与声音质量合格。

## 当前工作流检查什么

H3 检查文生视频、首尾帧或参考模式的实际分支，包括编码器、视频/音频 VAE、采样和解码节点。启用 LoRA、参考图、反向提示词或双时钟采样时，依赖会随配置变化。

Krea 检查文本生成或图像编辑节点；SDXL 检查文生图、图生图、可选外置 VAE 和 LoRA。参考图需要存在于当前后端。已知模型架构冲突会被标记为错误，未知自定义模型名称仍须实际加载验证。

API 图和工作流包根据真实节点及模型加载器的枚举输入检查，不会统一套用图片模型清单。空图、错误连线、参数类型或枚举不兼容会阻止有效编译。工作流包应先填写必需字段，尤其是图片上传，再检查本次配置。

本地文件检查只定位所选模型，不递归扫描模型库。对 safetensors 检查有界文件头、张量形状、数据偏移和文件长度，能够发现部分截断或结构错误；该检查不是全文件 SHA-256 校验，也不能证明权重内容与官方版本一致。

## 交给 AI 补齐环境

环境中心提供“复制修复提示词”和“导出脱敏报告”。它们用于交给 AI 或记录检查结果，本地安装路径会被隐藏；安装路径在本地发现面板中仍可见，方便你判断对应环境。

修复建议应先区分未安装、未运行、未连接和证据不足，再说明官方来源、兼容版本、下载大小、校验方式及对现有工作流的影响。当前版本只提供检测与建议，不会自动安装依赖或下载模型。

修复推理依赖时，应针对已有 ComfyUI 使用的环境，不要把 CUDA、PyTorch 或节点插件安装到 FrameWeave 的客户端环境。保留原来的模型目录和兼容路径，完成修复后重新扫描，再用短时长或小尺寸任务验证。

官方入口：[ComfyUI 系统要求](https://docs.comfy.org/installation/system_requirements)、[H3 原生工作流](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native)、[Krea 2 工作流](https://docs.comfy.org/tutorials/image/krea/krea-2)。工作流复用参见 [工作流包使用说明](WORKFLOW_PACKAGES.md)。
