# 模型功能与 LoRA 用途分类

先选择要完成的创作，再选择模型类型和兼容架构。

| 功能入口 | 包含的资产 |
| --- | --- |
| 图片创作 | 绘图、图像编辑、图片 LoRA、已绑定架构的配套模型 |
| 视频制作 | 视频生成、视频 LoRA、配套组件、Topaz 视频处理资产 |
| 语言与对话 | 语言模型和相关模型包 |
| 语音与音乐 | 配音、声音、音乐及其配套模型 |
| 视觉工具 | 识别、分割、视觉分析组件 |
| 通用组件 | 尚未绑定创作用途的编码器、VAE、Embedding 等 |
| 用途待确认 | 现有记录不足以确定用途的资产 |

功能入口的数量统计当前位置范围内的全部类型；下方的主模型、LoRA、配套组件和搜索条件进一步缩小结果。架构筛选继续保留，用于核对兼容性；归入同一用途不表示模型可以混用。

## 图片和视频 LoRA

LoRA 用途支持多选：风格画风、角色人物、光照氛围、细节材质、姿态构图、服饰造型、场景物件、动作运镜、采样加速、其他概念。没有足够依据的保留为“用途待补充”。

- 点击用途标签可筛选该用途的 LoRA。
- 模型详情 → 调整分类，可以修改功能归属和 LoRA 用途。
- 勾选本页模型 → 批量分类，可同时整理多份模型。可以只修改一个分类维度，另一个保持原样。
- “自动识别 / 使用自动建议”清除对应维度的手动覆盖；“恢复自动分类”清除所选模型的全部分类覆盖。
- 分类保存在本机数据库的独立 `model_labels` 表中，正常扫描不会覆盖。分类操作不会移动或改写模型权重。

## 自动分类依据

功能分类优先使用模型类型、内嵌架构与已有台账证据，明确区分图片、视频、语言和音频。Qwen 语言模型与 Qwen-Image 分开；尚不能绑定用途的 Qwen 文本编码器放入通用组件。MiniMax H3 主要归入视频，Music3 归入音频。架构记录本身含推断时，分类依据也会保留这一点。

LoRA 用途参考专用用途字段、标题/描述/标签、明确的名称线索和原来的用途目录。文件名与目录提供的是用途建议，并不构成实际效果验证。SDXL Lightning 等加速模型不会因名字相近被归入光照；细节增强也不会仅因过去存放在加速目录就被当成加速模型。

旧的 `Style_Other` 和 `Detail_Light` 都是混合分组，不能直接变成确定的单一用途。训练标签中大量出现某种人物，也不能证明这是一份角色 LoRA。没有进一步证据时保持待补充，用户分类始终优先。

本次没有进行模型推理或训练。分类依据可在每份模型详情中展开查看。
